# 빅카인즈 지역이슈 링크 점검기

## 프로젝트 소개

이 프로그램은 빅카인즈 지역이슈 큐레이션 페이지에서 사용자가 지정한 날짜와 지역을 순회하며, 각 이슈에 연결된 뉴스·공지사항 링크가 실제로 정상 동작하는지 Playwright Chromium으로 점검하고 Excel 결과를 생성합니다.

- 대상 페이지: [빅카인즈 지역이슈 큐레이션](https://www.bigkinds.or.kr/regional/curation.do)
- 현재 확인한 실행 환경: Python 3.12.10

프로그램의 핵심 목적은 정상 기사 URL을 추정하거나 복구하는 것이 아닙니다. 빅카인즈 출처 카드에 현재 연결된 실제 링크를 사용자가 클릭했을 때 정상적인 기사 또는 공지 화면이 표시되는지를 확인합니다. 추정 URL은 진단 정보로만 다루며 링크의 Y/N 판정에는 사용하지 않습니다.

## 주요 기능

현재 코드에는 다음 기능이 구현되어 있습니다.

- 시작일과 종료일의 대화형 입력 및 명령행 입력
- 시작일과 종료일을 모두 포함하는 날짜 범위 순회
- 전체 또는 선택 지역 점검
- 전체 17개 시도 선택
- 단일 지역 및 쉼표로 구분한 복수 지역 선택
- 날짜·지역별 이슈 목록 순회
- 이슈 상세 팝업의 `뉴스`, `공지사항` 출처 카드 수집
- 출처 카드 한 건당 Excel 한 행 생성
- 동일 이슈 안의 동일 원본 URL 중복 제거
- 빅카인즈 출처 카드의 실제 링크와 클릭 동작을 기준으로 검사
- 새 탭, 현재 탭 이동 및 리다이렉트 처리
- 정상 기사, 404·삭제 안내, 접근 제한, 서버 오류, 타임아웃, 클릭 오류, 빈 화면, 확인 필요 판정
- 기본 headless 백그라운드 실행과 `--headed` 디버깅 실행
- Excel 보고서 생성 및 저장 후 재검증
- `점검결과`, `오류목록`, `점검요약`, `디버그로그` 시트 생성
- 비정상 판정 및 일부 팝업·클릭 실패 시 스크린샷 저장
- 체크포인트 저장과 `--resume` 재개
- 날짜, 지역, 타임아웃, 재시도 횟수 등을 지정하는 명령행 인자

Playwright trace 저장 디렉터리는 설정에 정의되어 있지만, 현재 `main.py` 실행 흐름에는 trace를 자동 시작·저장하는 기능이 구현되어 있지 않습니다.

## 동작 방식

1. 사용자가 시작일과 종료일을 입력합니다.
2. 전체 지역 또는 일부 지역을 선택합니다.
3. Playwright Chromium을 기본 headless 모드로 실행합니다.
4. 빅카인즈 지역이슈 페이지에 접속합니다.
5. 날짜와 지역을 순차적으로 선택합니다.
6. 각 지역의 이슈 카드를 순회합니다.
7. 이슈 상세 팝업에서 뉴스·공지사항 출처 카드를 수집합니다.
8. 출처 카드의 실제 URL과 클릭 동작을 확인합니다.
9. 열린 대상 페이지의 HTTP 상태, 최종 URL, 제목, 본문 후보 및 오류 화면을 확인합니다.
10. `링크작동여부_YN`과 세부 판정을 생성합니다.
11. 각 결과를 체크포인트에 기록하고 날짜·지역 완료 상태를 저장합니다.
12. 누적 결과로 최종 Excel 보고서를 생성합니다.

## URL 필드 설명

### 원본URL

빅카인즈 출처 카드가 실제로 가리키며 사용자가 클릭할 때 브라우저가 사용하는 URL입니다. 링크 검사와 Y/N 판정의 출발점입니다.

### 최종URL

원본 URL을 Chromium에서 열고 페이지 이동과 리다이렉트가 끝난 뒤 브라우저에 남은 URL입니다.

프로그램은 잘못된 빅카인즈 URL을 정상적인 언론사 URL로 임의 보정해 Y로 판정하지 않습니다. 코드가 추정 가능한 URL을 발견하더라도 진단용 필드에만 기록하며, 실제 빅카인즈 링크의 검사 결과를 바꾸지 않습니다.

## 링크작동여부_YN

- `Y`: 실제 빅카인즈 링크를 통해 정상적인 기사 또는 공지 화면을 확인한 경우
- `N`: 404·삭제 안내, 접근 제한, 서버 오류, 타임아웃, 클릭 오류, 빈 화면 또는 정상 기사 확인 불가인 경우

HTTP 200만으로 정상 판정하지 않습니다. HTTP 상태가 200이어도 렌더링된 페이지가 404·삭제 안내, 접근 제한 또는 오류 화면이면 `N`입니다. 반대로 정상 판정에는 실제 페이지에서 기사 제목과 본문에 해당하는 렌더링 근거가 필요합니다.

## 설치 방법

`requirements.txt`에는 Playwright, openpyxl, pytest가 정의되어 있습니다. 별도의 Python 최소 버전 메타데이터는 없으며, 현재 프로젝트 환경에서 확인된 Python 버전은 3.12.10입니다. Windows에서 Python 3.12를 사용하는 설치 예시는 다음과 같습니다.

```powershell
py -3.12 -m venv .venv
.venv\Scripts\activate
python -m pip install --upgrade pip
pip install -r requirements.txt
python -m playwright install chromium
```

## 실행 방법

### 대화형 실행

날짜나 지역 인자를 생략하면 콘솔에서 입력 또는 선택할 수 있습니다.

```powershell
python main.py
```

### 날짜 지정

```powershell
python main.py --start-date 2026-07-08 --end-date 2026-07-08
```

### 전체 지역

```powershell
python main.py --start-date 2026-07-08 --end-date 2026-07-08 --regions 전체
```

### 일부 지역

```powershell
python main.py --start-date 2026-07-08 --end-date 2026-07-08 --regions 충청북도,충청남도
```

### 브라우저 표시 디버깅

```powershell
python main.py --start-date 2026-07-08 --end-date 2026-07-08 --regions 충청북도 --headed
```

### 체크포인트에서 재개

```powershell
python main.py --start-date 2026-07-08 --end-date 2026-07-08 --regions 충청북도 --resume
```

### 지원하는 명령행 인자

| 인자 | 현재 동작 |
| --- | --- |
| `--start-date YYYY-MM-DD` | 시작일 지정 |
| `--end-date YYYY-MM-DD` | 종료일 지정 |
| `--regions 지역1,지역2` | 지역 이름 목록 또는 `전체` 지정 |
| `--headed` | 브라우저 창을 표시하여 실행 |
| `--resume` | 동일 날짜·지역 조건의 기존 체크포인트에서 재개 |
| `--max-issues N` | 날짜·지역별 점검할 최대 이슈 수 제한 |
| `--timeout 초` | 링크 검사 타임아웃 지정, 기본값 30초 |
| `--retries N` | 링크 검사 재시도 횟수 지정, 0~2, 기본값 2 |
| `--link-delay 초` | 링크 검사 사이 대기 시간 지정, 기본값 0.5초 |
| `--debug` | 인자는 정의되어 있으나 현재 별도의 동작 분기는 없음 |

## 출력 파일

정상 완료뿐 아니라 중단 또는 오류가 발생한 경우에도 그때까지 체크포인트에 누적된 결과로 Excel 저장을 시도합니다.

- `output/`: 최종 Excel 보고서 저장. 파일명은 `bigkinds_regional_link_audit_시작일_종료일_실행시각.xlsx` 형식입니다.
- `work/`: 체크포인트 JSONL과 실행 로그 저장. 체크포인트 파일은 날짜 범위와 지역 선택을 반영하며, 로그 파일은 `audit_시작일_종료일_실행시각.log` 형식입니다.
- `artifacts/screenshots/`: 비정상 링크 판정과 일부 팝업·클릭 실패 화면의 PNG 스크린샷 저장.
- `artifacts/traces/`: 수동 진단 trace를 둘 수 있는 경로입니다. 현재 일반 실행에서는 trace ZIP을 자동 생성하지 않습니다.
- `logs/`: 현재 프로그램이 사용하는 로그 경로가 아닙니다. 실행 로그는 `work/`에 저장됩니다.

`output/`, `work/`, 스크린샷, trace, 로그 및 생성된 Excel·CSV 결과는 Git 저장소에 포함하지 않도록 `.gitignore`에서 제외합니다.

## Excel 구성

- `점검결과`: 중복 제거된 전체 출처 링크의 메타데이터, URL, HTTP 상태, 판정 및 진단 결과
- `오류목록`: 최종 판정이 `정상`이 아닌 행만 모은 목록
- `점검요약`: 실행 조건, 전체 건수, 날짜·지역별 통계 및 판정별 건수
- `디버그로그`: 클릭 방식, URL 이동, 렌더링 근거 및 오류·접근 제한 판정 근거 등 상세 진단 정보

## 테스트

전체 자동화 테스트는 다음 명령으로 실행합니다.

```powershell
python -m pytest -q
```

테스트에는 날짜·지역 처리, URL 정규화와 중복 제거, 판정 규칙, Excel 생성 및 로컬 HTTP 서버를 이용한 브라우저 흐름 검증이 포함됩니다. 자동화 테스트는 실제 빅카인즈 운영 사이트에 의존하지 않습니다.

실제 사이트를 소규모로 확인하려면 현재 지원되는 `--max-issues` 옵션을 사용합니다.

```powershell
python main.py --start-date 2026-07-08 --end-date 2026-07-08 --regions 충청북도 --max-issues 1
```

## 주의사항

- 기사 본문을 수집하거나 보관하기 위한 프로그램이 아닙니다. 페이지 내용은 링크 상태 판정을 위해 실행 중에만 검사합니다.
- 빅카인즈에 현재 연결된 링크의 동작 상태만 점검합니다.
- 접근 제한, 로그인 또는 CAPTCHA를 우회하는 기능은 없습니다.
- 빅카인즈나 언론사 사이트의 DOM이 변경되면 선택자를 수정해야 할 수 있습니다.
- 긴 날짜 범위와 전체 17개 지역을 점검하면 실행 시간이 오래 걸릴 수 있습니다.
- 현재 구조화 로그와 디버그 필드는 저장 전에 쿠키, 토큰, 인증 헤더 등 알려진 민감 값을 마스킹합니다.
- 외부 도구로 별도 생성한 네트워크 덤프나 수동 trace는 이 마스킹 경로를 거치지 않을 수 있으므로 Git에 포함하지 말고 별도로 점검해야 합니다.
